\section{Related Work}
\label{sec:related}

% Paper 1: TestCTRL - ChatGPT Unit Test Generation
\subsection{Chain-of-Thought Prompt and Reinforcement Learning for Test Generation}

Yuan and colleagues~\cite{yuan2025testctrl}, observed that unit tests generated by large language models (LLMs) often have low coverage and fail to fully reflect the meaning of the code.

To overcome this problem, they developed a framework called TestCTRL that combines chain-of-thought prompts with reinforcement learning; the model updates its policy by receiving coverage feedback while generating tests.
As a result, they achieved significant increases in branch coverage and line coverage compared to basic LLM methods.
In our project, we are similarly running an iterative test optimization process with ChatGPT; however, instead of automatic reinforcement learning as in TestCTRL, we are using a manual feedback loop.

% Paper 2: HumanEval-XL - Benchmark for Code Generation
\subsection{Multilingual Code Generation Benchmarks}

Peng and colleagues~\cite{peng2024humanevalxl}, noticed that most existing code generation test suites relied on English natural language descriptions, which was insufficient for measuring the performance of LLMs in different languages.
Therefore, they created HumanEval-XL by expanding the original HumanEval dataset to 23 natural languages and 12 programming languages.
The study revealed that benchmarks using only English underrepresented the code generation ability of LLMs, and showed significant performance drops, especially in low-resource languages.
The HumanEval-Java subset we used is also part of this multilingual dataset; we are focusing only on Java problems and comparing two LLMs on this subset.

% Paper 3: Meta ACH - Mutation Testing at Scale
\subsection{Industrial-Scale Mutation-Guided Test Generation}

Foster and colleagues~\cite{foster2025mutation}, at Meta, presented an LLM-based mutation testing framework to improve large-scale test generation.

Instead of generating random mutants, they created realistic mutants using code-understanding LLMs, and then generated tests to kill these mutants; they also integrated a mechanism to detect semantically equivalent mutants. This system has been applied to tens of thousands of classes in Facebook, Instagram, and WhatsApp codebases, resulting in significant improvements in mutant detection rates. In our project, we are also conducting manual mutation testing on selected problems within Phase 1; although we are far from industrial scale, we are applying the idea of generating mutants with LLMs to a limited extent.

% Paper 4: CoverUp - Coverage-Guided Generation
\subsection{Iterative Coverage-Guided Test Generation}

Pizzorno and Berger~\cite{pizzorno2024coverup}, starting from the premise that tests generated by LLMs initially have insufficient coverage, developed a tool called CoverUp that works with coverage feedback.

CoverUp analyzes the row and branch coverage of the generated tests, translates the uncovered parts into natural language, and prompts the LLM to generate new tests; this cycle continues until coverage is saturation. In experiments, row coverage increased from an average of 54\% to 61\%, and branch coverage from 34\% to 43\%.
Our test improvement step, similar to CoverUp, uses coverage reports to generate new tests in ChatGPT and Gemini; however, the process is not fully automated, but driven by researcher intervention.

% Paper 5: Prompt Engineering Guidelines
\subsection{Empirical Guidelines for Code Generation Prompts}

Midolo and colleagues~\cite{midolo2026guidelines}, systematically investigated how the quality of prompts used when generating code from LLMs affects the outcome.

By experimenting with different prompt patterns (in terms of specificity, instance insertion, context richness, etc.), they observed that certain prompt patterns significantly improved code correctness.
They also highlighted the differences between prompt engineering and model fine-tuning, demonstrating that a well-designed prompt is sufficient in most practical scenarios.
Our reason for choosing a semi-agent approach in our study is based on these findings; we try to reach the most effective prompt pattern by manually designing the prompts and evaluating the results in real-time.

% Summary paragraph connecting all papers
\subsection{Summary and Positioning}

The five studies above offer complementary perspectives on LLM-based test generation.

TestCTRL and CoverUp highlight the idea of iterative improvement, while Meta's ACH system combines industrial-scale mutation testing with LLM; we apply a limited subset of these techniques in a semi-agent manner by performing an in-depth comparison on 30 HumanEval problems.

HumanEval-XL emphasizes the importance of multilingual benchmarking and forms the basis of our Java-focused evaluation; Midolo et al.'s prompt engineering guide helps us select the correct prompt structure in our manual iterations.
